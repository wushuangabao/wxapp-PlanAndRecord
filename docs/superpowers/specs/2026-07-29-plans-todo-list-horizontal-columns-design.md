# 计划页 TODO LIST 横向任务列设计

## 目标与范围

将计划页 TODO LIST 从纵向可滚动的密集条目改为固定高度的横向任务列，使用户在不改变任务语义的前提下，一次聚焦三个待办事项。

- 保留既有任务排序：未完成 `todo` 在已完成 `completed` 前，同一状态按最近更新时间倒序。
- 保留勾选、关联项目、取消关联、删除二次确认和右下角新建 TODO 的行为。
- 不修改任务、项目、日历事件或日志的数据模型，也不改变项目关联和删除规则。
- 不引入图片、第三方图标库或网络资源；链接和垃圾桶以 WXSS 绘制的线性图标呈现。

## 布局设计

TODO 卡片固定为 `420rpx` 高。去掉任务行间分割线，列表可视区由 3 个等高任务行组成，3 条任务恰好填满其高度。

任务按当前排序每 3 条投影为一个任务列：第 1 至 3 条在第一列，第 4 至 6 条在第二列，依此类推。每列宽度为列表可视区的 60%，相邻列以列表宽度的 20% 留白；静止时显示一个完整列，并显示右侧相邻列约三分之一，且前一列的操作图标不会与后一列的完成方框拥挤；最后一列仍可横向对齐到可视区左侧。

每个任务行左侧是完成方框；中部是单行任务标题，若仍关联项目则在标题下显示项目名称小字；右侧依次是链接和垃圾桶图标按钮。完成态沿用低对比与删除线，不增加新的状态语义。

## 交互设计

外层使用仅启用横向滚动的 `scroll-view`，不设置纵向滚动。控制器测量相邻列起点的实际距离（列宽加列间距）作为吸附步长；列容器末尾保留一个不可见的 `20%` 尾随占位，使最后一列也能滑到可视区左侧，避免不同设备上出现不一致的露出比例或未对齐的横滑终点。

开始触摸时记录触点位置和当前列；结束触摸时：

- 向左或向右越过最小手势阈值，分别移动到下一列或上一列；
- 轻点或未达到阈值时，吸附到当前最接近的整列；
- 到达首列或末列时不越界。

通过受控的 `scroll-left` 与动画回写列起点，避免停在两列之间。链接图标继续打开现有项目关联菜单；垃圾桶图标继续打开现有删除确认框。图标按钮保留可访问名称，不能以隐藏文字按钮替代。

## 实现边界

仅修改以下文件：

- `docs/product-design.zh-CN.md`：更新 TODO LIST 的正式交互定义。
- `miniprogram/pages/plans/index.js`：构造三条一组的列投影、测量列宽、管理横向吸附状态与手势事件。
- `miniprogram/pages/plans/index.wxml`：替换 TODO 列表的滚动结构及图标按钮。
- `miniprogram/pages/plans/index.wxss`：定义固定三行、横向列宽、图标和完成态样式。
- `tests/plans-page.test.js` 与相关页面静态回归测试：覆盖分列、手势吸附和新的 WXML 结构。

工作区中已存在的 `index.wxml`、`index.wxss` 未提交改动属于用户修改：标题的中文括号计数与“关联项目”语义会被保留，但这两个文字按钮本身会依照本设计替换为图标按钮。

## 验收与验证

自动化测试应覆盖：任务按三个一组分列；向左、向右及边界手势计算出正确列起点；关联与删除仍使用稳定任务 ID；页面不再启用 `scroll-y`，并提供横向滚动与两个图标按钮。

在微信开发者工具中验证：空列表、恰好 3 条、4 至 6 条、7 条以上、关联项目副标题、长标题、完成态、横向轻划吸附、关联菜单、删除确认与底部安全区。真机触控手感单列为人工验收项。
