# 项目视图内联子任务设计

> 状态：已确认，实施计划已生成，等待选择执行方式
> 日期：2026-08-05
> 范围：`miniprogram/pages/plans/` 的活动项目列表

## 1. 背景与目标

当前项目区将子任务作为二级入口：项目标题打开只读的子任务弹层，列表本身只显示项目名、截止时间、“+子任务”和“管理”。当活动项目较多时，每个项目所占空间主要是低频操作，用户不能在项目视图直接看到要做什么。

本次将项目区调整为紧凑的项目—子任务总览，让用户在项目页首屏就能看到每个项目最紧急的未完成行动。目标是提高信息密度和直接完成任务的效率；不新增项目进度、统计或数据字段。

## 2. 保持不变的边界

- `Project` 仍只保存现有字段，不增加完成率、进度或聚合字段。
- `Task.status` 仍只有 `todo` 与 `completed`；勾选只复用现有切换任务状态的服务调用。
- 项目、任务、计划块、时间日志的关系、写入规则和计时规则均不变。
- TODO LIST、愿望区、已归档项目、全局导航和项目新建上限均不在本次重构范围内。
- 编辑、归档和放弃项目仍分别使用现有编辑表单、二次确认和管理逻辑。

因此，界面不得显示“2/5 完成”、百分比、进度条或任何项目进度聚合；只显示任务条目本身及“已完成 N 项”的折叠入口。

## 3. 页面结构

活动项目继续放在一个“项目（N / 5）”内容面内，右上角保留新建项目 `+`。各项目以细分隔线分组，不为每个项目再嵌套独立大卡片。

每个项目分组自上而下为：

1. 项目标题与右上角紧凑 `…` 管理按钮；标题不再用于打开子任务弹层。
2. 截止时间辅助文字。
3. 最多三条未完成子任务行。
4. 条件显示的“查看全部 N 项”与“已完成 N 项”折叠入口。
5. “+ 添加子任务”文本操作。

示意：

```text
项目（4 / 5）                                      ＋
──────────────────────────────────────────────
2222                                            ···
截止：2026-07-31 17:30
□ 整理资料
□ 确认目录
□ 撰写第一节
查看全部 2 项   ·   已完成 1 项
＋ 添加子任务
```

项目没有未完成任务时，第三部分改为一行低强调空状态“还没有子任务”，并保留“+ 添加第一项子任务”；不得保留固定高度占位。

## 4. 交互与状态

### 4.1 默认与展开

- 默认按现有任务保存顺序显示前三条 `todo` 子任务。
- 未完成任务超过三条时，显示“查看全部 N 项”；点击后仅展开当前项目剩余未完成项，文案切换为“收起”。
- 展开状态仅是页面内暂态，不持久化；页面重新进入后恢复默认三条。
- 任务数不超过三条时，不显示“查看全部”。

### 4.2 子任务行

- 每一行左侧为与 TODO LIST 一致的勾选框，点击后在 `todo` 与 `completed` 间切换，并沿用当前成功提示。
- 子任务标题点击进入与 TODO LIST 相同的行内标题编辑态；不在项目区新建另一套表单。
- 完成任务立刻从默认未完成列表移除，并更新“已完成 N 项”入口；重新打开已完成任务时回到未完成列表的现有保存顺序位置。
- 标题超过单行时使用省略，整行保持稳定高度，避免挤压勾选热区。

### 4.3 已完成子任务

- 有完成子任务时显示“已完成 N 项”；默认折叠。
- 点击后在当前项目中显示完成任务行，使用现有完成态的低对比与删除线，并提供同样的重新打开勾选操作。
- 未完成任务和已完成任务各自展开互不影响；项目之间的展开状态也互不影响。
- 没有完成任务时不渲染该入口。

### 4.4 项目操作

- “+ 添加子任务”直接打开已预选当前项目的任务编辑表单。
- `…` 打开现有项目管理菜单，包含编辑项目、归档项目、放弃项目。
- 删除原有独立的“管理”文字按钮和标题右侧“子任务”跳转标签。
- 原“项目标题打开只读子任务弹层”的入口及弹层由卡内展开替代；不再保留重复的只读任务列表。

## 5. 视觉规则

- 维持暖灰白页面基底和暖白内容面；项目间使用低对比细分隔线，而非多层卡片、厚阴影或高饱和色。
- 项目标题为唯一强层级；截止日期为辅助层级；子任务标题为正文层级。
- 勾选框、完成态和文本操作复用 TODO LIST 的已有状态语义；绿色只用于可完成动作和当前选择。
- `…` 为固定尺寸、带无障碍标签的 `view` 点击区，不使用窄容器内的原生 `button`，避免 iOS 默认外边距导致布局挤压。
- 所有可点击项保留至少 56rpx 的热区；页面底部仍为原有滚动容器和 tabBar 安全区留白。
