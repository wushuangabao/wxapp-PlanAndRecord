# 计划页 TODO LIST 与项目入口重构（已实施）

> 状态：已实施并归档。核心任务语义与上下文入口已于 2026-07-29 落地；TODO LIST 的纵向列表方案随后由[横向任务列设计](./2026-07-29-plans-todo-list-horizontal-columns-design.md)替代。
>

## 实施结果与后续演进

- `Task.status` 已收敛为 `todo / completed`，独立 TODO、项目子任务、编辑、关联、取消关联和二次确认删除入口均已实施。
- 本文最初提出的固定高度纵向滚动列表已被“三条一列、横向吸附”的后续设计替代。
- 独立 TODO 的新增入口最终位于 TODO LIST 标题区；本文所述右下角悬浮按钮不再是当前交互。
- 本文最初提出的“删除任务只断开全部引用”语义已被产品基线 5.2 的最终规则替代：未结束的关联计划及相应重复数据按规则删除，历史计划、日志和计时草稿保留并断开失效引用。
- 本文历史拟议语义中“日历事件或日志自身的 `projectId`”示例也已失效：自 2026-07-30 起，当前关系以 `TimeLog → 计划块实例 → Task → Project?` 为准，旧 direct ID 仅作 JSON 只读兼容。
- 自动化回归已经覆盖核心任务流程；完整模拟器矩阵与真机触控体验仍未完成，不在本文中标记为已验收。

## 背景与目标

当前计划页在活动项目之前展开完整的新建项目、OKR、愿望池和任务收集表单，首屏元素过多。此前产品基线要求项目列表位于顶部；本次交互决定以更高频的全局任务清单优先：`TODO LIST` 固定高度地显示在项目列表之前，项目仍是页面的第二个主要区块。

本次重构的目标是：

1. 删除计划页的“任务收集”模块及其独立全量任务卡片；任务不再具有 `inbox` 收集状态。
2. 统一任务的新增入口：项目条目内创建关联项目的子任务；右下角悬浮按钮创建无关联项目的独立 TODO。
3. 在一个紧凑、可滚动的 `TODO LIST` 中管理所有任务的完成、项目关联与删除。
4. 保留愿望池、项目、OKR、归档和放弃的既有领域边界；布局重构本身不自动删除任务或隐式丢弃关联历史。

## 方案比较与选择

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 顶部 TODO LIST + 右下角新增（选用） | 所有任务在固定高度清单中管理；项目内和全局入口分别创建关联/无关联 TODO。 | 满足已确认交互，首屏层级明确。 |
| B. 保留折叠的“任务收集” | 保持 `inbox` 入口，只把表单折叠。 | 不选用：仍保留用户要求移除的模块和二次整理步骤。 |
| C. 跳转独立任务页 | 将 TODO 放到新页面。 | 不选用：扩大导航范围，破坏计划页的项目—任务近距离关系。 |

## 页面结构与视觉层级

页面顺序固定为：

1. 现有页眉与标题；
2. 固定高度的 `TODO LIST`；
3. 活动项目列表；
4. 已归档项目（有数据时）；
5. 默认收起的愿望池。

不再渲染“添加关键结果”的全局表单和“任务 / 备忘录”模块。新建项目、添加 OKR、添加子任务均由上下文入口打开底部弹层。底部弹层复用页面已有的遮罩、圆角和安全区样式，不引入新的视觉系统。

### TODO LIST（初版布局，已被横向任务列设计替代）

- TODO LIST 卡片总高度固定为 `420rpx`，其中标题区固定、任务 `scroll-view` 占其余高度并纵向滚动；没有任务时仍保留该高度并显示简短空状态。
- 显示全部本地 `Task`：未完成（`todo`）在前，已完成在后；同一组按最近更新时间倒序。这样保留完成任务的重新打开能力，同时保持列表语义清晰。
- 每行采用固定行高，顺序为：可点击的方框、任务标题、可选项目名称小字、`关联`、`删除`。项目名称只在 `projectId` 存在时显示；标题优先占用可用宽度。
- 点击方框：非 `completed` 任务变为 `completed`；已完成任务变为 `todo`。已完成样式使用低对比文字与勾选状态，不增加额外卡片。
- 点击 `关联`：使用选择菜单，第一项始终为“取消关联”，其后列出可关联的活动项目。选择项目时写入该项目 ID 和名称快照；选择“取消关联”仅清除关联，不删除任务。
- 点击 `删除`：先显示明确的确认框，再执行原子删除，不能只从页面数组中移除。

### 创建任务

- 右下角固定的圆形 `+` 悬浮在原生 tabBar 与安全区之上。点击后打开“新建 TODO”底部弹层；弹层仅填写任务标题，保存时创建 `status = todo`、`projectId = null` 的任务。
- 每个活动项目条目展示高频的 `OKR` 与 `+子任务` 操作。`+子任务` 打开标题输入弹层，保存时创建 `status = todo` 且关联当前项目的任务。
- 项目标题可点击打开“项目子任务”弹层。弹层按未完成/已完成两页签显示当前项目关联任务；首版仅显示任务名称。这个查看入口不承担新增任务，避免一个弹层同时承担浏览和表单两种主任务。

### 项目与其他区块

- 活动项目标题显示数量；列表末尾右对齐的 `+` 打开“新建项目”底部弹层。达到 `MAX_ACTIVE_PROJECTS` 时隐藏该入口，领域服务仍保留上限校验。
- 新建项目弹层保留项目标题、截止日期、首个目标、首个 KR 与当前值；服务仍要求至少一个含 KR 的目标。
- `OKR` 操作打开携带稳定项目 ID 的底部弹层，提交时以最新项目的完整 objectives 聚合更新，避免使用数组下标。
- 愿望池继续位于项目之后，默认收起；展开后保留现有的愿望创建、编辑和转换能力。
- 编辑、归档、放弃属于低频项目管理动作，收进一个紧凑的“管理”文本操作；点击后以原生选择菜单展示，避免与 `OKR`、`+子任务`并列造成项目行过密。

## 任务数据契约

### 状态与存储边界

- 新增的独立 TODO 和项目子任务一律创建为 `todo`；计划页不再创建或展示 `inbox`。
- `Task.status` 仅保留 `todo / completed`；勾选完成变为 `completed`，重新打开变为 `todo`。
- 当前处于早期开发，没有需要保留的用户 `inbox` 数据；不提供迁移、读取兼容或导入兼容。任何遗留的本地开发快照应清空后重新创建。

### 删除任务（历史拟议语义，已被最终规则替代）

> 下列内容记录设计演进，不是当前规则。当前删除范围与历史保全要求见[产品设计基线 5.2](../../product-design.zh-CN.md#52-核心数据边界)。

新增 `ApplicationService.deleteTask(id, confirmed)`，且 `confirmed !== true` 时拒绝执行。确认后在同一事务中：

1. 删除目标 `Task`；
2. 保留日历事件、重复规则、例外、候选/已确认日志、进行中计时草稿和恢复草稿，但清空其中的失效 `taskId`，并写入或保留任务名称快照；
3. 不隐式删除日历计划、重复规则或日志，避免“删除一个 TODO”连带丢失计划或实际记录；
4. 保留其他有效关联（例如日历事件或日志自身的 `projectId`），因为删除任务不等于取消项目归属。

这一定义不同于“放弃项目”的级联删除：任务删除是用户显式的窄范围删除，优先保留计划与事实，使用快照维持可追溯性。

### 验收与回归

1. 默认首屏先出现固定高度 TODO LIST，再出现活动项目；不存在任务收集模块或全局任务表单。
2. TODO LIST 标题区的 `+` 创建无项目 `todo`；项目内 `+子任务` 创建关联项目 `todo`；两者都不新建 `inbox`。
3. TODO 行可完成、重新打开、关联项目、取消关联和确认删除；状态枚举中不再存在 `inbox`。
4. 删除任务后，关联日历、规则、例外、日志和计时草稿符合产品基线 5.2 的最终删除与历史保全规则，且其他有效项目关联不受影响。
5. 项目标题可按状态查看子任务；活动项目达到上限时不允许新增项目，但不影响新增 TODO。
6. 运行 `npm test`；在微信开发者工具编译计划页，检查默认态、空态、长标题、5 个项目、任务滚动、各弹层、tabBar 避让和安全区。真机体验单独标记为待人工确认。
