# 小程序简约风格 UI

## 核心原则

先按用户意图选择且只执行一个入口。评审默认只读；只有用户明确要求设计、重构、实现或修改时才获得源文件写入授权；验证本身不构成写入授权。

## 入口路由

| 用户意图 | 执行分支 | 写入权限 | 交付 |
| --- | --- | --- | --- |
| 评审、审查、检查、给建议 | 评审 | 禁止修改文件 | “问题—证据—建议”报告 |
| 设计、重构、实现、按建议修改 | 设计 / 重构 | 可修改约定范围内的文件 | 改动、验证与人工确认项 |
| 验证、编译、截图、回归 | 验证 | 默认只读；不得借验证修复代码 | 验证矩阵与证据 |

用户同时明确要求评审和实现时，先完成当前状态评审，再进入设计 / 重构分支。意图仍不明确时按只读评审处理，并说明未写入。

## 公共准备

1. 读取目标页面的 `.js`、`.wxml`、`.wxss`、`.json` 和 `miniprogram/app.json`。
2. 涉及产品含义、记录、日历、统计或隐私时，读取 `docs/product-design.zh-CN.md`。
3. 读取 [风格参考](references/style-guide.zh-CN.md) 中的色彩、文字、按钮、卡片与布局参数；用户资料覆盖对应参数。
4. 从现有代码确认页面主任务、主操作、字段、状态、导航和领域语义；不得猜测业务数据。

## 评审分支：只读

1. 只检查代码、已有截图和可只读获取的运行证据；不得修改、格式化或生成仓库文件，不得以“顺手修复”为由进入写入。
2. 检查信息层级、状态区分、色彩语义、文字可读性、操作优先级、长文本、空状态、选中 / 禁用状态、滚动区域、底部安全区和原生 `tabBar` 遮挡。
3. 每个问题按“问题—证据—建议”输出：
   - 问题：描述可观察的用户影响，并标注严重程度。
   - 证据：给出文件与行号、现有截图或可复现状态；没有证据时标为待验证，不把推测写成事实。
   - 建议：给出最小可行修复及影响文件，不直接实施。
4. 若未发现问题，明确说明检查范围与未覆盖状态；不得为了充实报告制造问题。

## 设计 / 重构分支：允许写入

1. 先说明页面层级、关键状态、预计修改文件和保持不变的业务边界，再编辑代码。
2. 复用现有状态和事件处理；优先修改 WXML / WXSS，仅在界面确实需要时修改 JS / JSON。
3. 同步检查四类页面文件与 `app.json`，不得为视觉效果改变数据写入、确认语义、导航结构或全局配置。
4. 写入完成后执行验证分支；交付时列出实际改动、验证证据和仍需人工确认的体验。

## 验证分支：可操作闭环

1. 先检查 `.local/wechatide-path.txt` 是否存在、非空且指向有效的微信开发者工具目录。无效时继续静态检查，但停止依赖开发者工具的步骤并报告阻塞原因。
2. 静态检查页面是否在 `app.json` 注册、WXML 绑定与事件是否能在 JS 中找到、页面 JSON 是否有效，以及 WXSS 是否覆盖本次相关状态和安全区。
3. 路径有效时，使用 `wechatide-skill` 的编译能力打开目标页面并编译；记录成功结果或完整错误摘要。
4. 编译成功后，使用其调试能力截取模拟器证据。至少检查默认态，并按页面实际能力检查长文本、空状态、选中 / 禁用状态、滚动到底部及安全区；不适用项标记 `N/A`。
5. 编译失败时停止“截图通过”判定，保留错误证据并把相关项标记为失败。工具不可用、状态无法构造或未做真机测试时标记未验证，不得宣称通过。
6. 输出验证矩阵：`检查项 | 状态（通过/失败/N/A/未验证） | 证据 | 后续动作`。模拟器截图只能证明模拟器结果，真机体验必须单列。

## 设计与实现边界

- 用白色或暖灰白色留白建立安静感；绿色仅承担当前选择、主要确认和少量关键状态。
- 一页只保留一个视觉锚点；用低对比圆角容器组织成组选项，避免把所有内容都卡片化。
- 为主操作保留稳定位置和足够空白；危险、删除、取消必须维持自身语义。
- 避免强渐变、高饱和多色、厚阴影、密集描边、悬浮装饰和自动播放的抢眼动画。
- 使用微信小程序原生组件；图片提供有意义的 `alt`；底部操作预留 `env(safe-area-inset-bottom)`。
- 视觉改动不自动修改产品设计基线。若要求改变用户可见行为、领域语义、数据契约或隐私边界，先起草权威文档并等待确认。

## 路由示例

用户说“评审计时页 UI”时，只输出报告，即使修复很简单也不改文件；用户随后说“按建议重构”后，才进入写入与验证。

## 常见错误

- 把“评审”解释成“评审后顺手修改”。
- 只说“已编译”或只给一张默认态截图，没有验证矩阵和可定位证据。
- 工具不可用、编译失败或未做真机测试，却把结果写成通过。
- 为视觉调整改动业务状态、写入逻辑、确认语义或导航。
